# 安装与更新

## 安装

一条命令(npm / npx):

```bash
npx mm-gsd-core                 # 安装到用户技能目录 ~/.agents/skills/
npx mm-gsd-core install --local # 安装到当前项目的 ./.agents/skills/
npx mm-gsd-core install --hooks # 顺带安装宿主 hook(危险操作拦截 + 工具遥测,见[守卫](guards.md)与[遥测](telemetry.md))
```

- 零依赖,要求 Node 18 以上,跨 Windows / macOS / Linux。
- 装完是 8 个技能:讨论、计划、执行、验收、显式校验计划、诊断、流程总控,外加过程看板(可选项,见[看板](board.md))。
- 默认目的地是**用户级** `~/.agents/skills/`(本机所有项目共享);`--local` 只装进当前项目。

也可以手动安装:克隆仓库后把各技能目录拷进技能目录。手动拷贝没有版本清单,体检会如实报「版本不可追溯」。

### npx 还是 npm

两个入口干的是同一件事,区别只在**要不要在 PATH 上留一个常驻命令**:

| | `npx mm-gsd-core <子命令>` | `npm i -g mm-gsd-core` → `mm-gsd <子命令>` |
|---|---|---|
| 包落在哪 | npx 缓存(临时;首次要联网取) | 全局 node_modules,PATH 上多一条 `mm-gsd` |
| 每次跑 | 走缓存,基本瞬时 | 直接跑本地那份,零网络 |
| 适合谁 | 首装、临时体检、CI 里跑一次 | 天天要敲 `mm-gsd web` / `mm-gsd check` 的人 |

- **默认走 npx 就够**:大多数用户装一次 `npx mm-gsd-core install` 即可,之后在项目里让 agent 调技能 —— 技能装在 `~/.agents/skills/`,不依赖 PATH 上有没有命令。
- **要自己敲命令才需要全局 npm**:`install` 只把技能拷进安装目录,**不会**在 PATH 上给你加 `mm-gsd` 命令。想敲 `mm-gsd web` 起看板、或跨项目反复跑 `mm-gsd check`,全局装一次最省事。
- **全局装完注意版本对齐**:全局包与安装目录里那份是两个副本,会各走各的;`mm-gsd doctor` 比对两边指纹,报「装的是旧版」就 `mm-gsd update` 机械覆盖。

### 首装与更新的分工

- **install(首装)尊重已有内容**:同名技能已存在且内容相同就跳过;内容不同,先把原内容备份到用户主目录的 backups 目录(按技能名加时间戳命名),再覆盖。
- **update(更新)先对齐 registry 再机械覆盖**:先问 npm registry「最新发布的是哪一版」——
  - registry 上有更新的版本 → **先取那一版,再拿它的技能去盖**(所以全局装着旧版的机器敲一次 update 就能升上去);
  - registry 上比当前旧 → 不降级,按当前这份覆盖;
  - registry 问不到(离线 / 没装 npm)→ 按当前这份覆盖,并明确告诉你「问不到 registry」。
  - **已装的那份比要盖的还新 → 也不盖**(全局命令是旧版、主仓是新版的现场):直接告诉你「当前这份 mm-gsd 比已装的旧,先 `npm i -g mm-gsd-core` 刷新 mm-gsd 本身」。盖回旧版等于把用户已经升级到的新技能弄丢。
  - 覆盖本身不比对、不提问,已装技能与宿主卡直接盖成包里这份。真有自定义需求的用户应该改技能定义本身,而不是指望更新保留本地改动。

```bash
npx mm-gsd-core update          # 对齐 registry 上的 latest,再覆盖更新用户级安装(宿主卡一并刷新)
npx mm-gsd-core update --next   # 跟预发布通道(next):要新功能的人用这个
npx mm-gsd-core update --local  # 只更新当前项目的安装(跳过宿主卡)
```

**全局装着旧版、想升到最新**:先 `npm i -g mm-gsd-core` 刷新全局命令本身,再 `mm-gsd update` 刷新技能目录 —— 两个副本各走各的,少一步就有一份还是旧的。

**新出的技能怎么到宿主那里**:宿主技能目录里放的是指向技能主仓的链接(内容跟着主仓变),
但**新增的技能名**不会自己长出来 —— `update` 会把缺的链接补上(只补缺的,不重建已有的)。

## 版本与体检

- `mm-gsd --version` 打印版本号。
- 每次安装 / 更新都会在安装目录写一份**版本清单**:版本、来源、时间、每个技能的指纹。
- `npx mm-gsd-core doctor` 只读体检:宿主环境、每个技能的已装状态、已装版本与当前包的差异 —— 有漂移会提示「跑一次 update 机械覆盖」,动词统一,不让你猜。

## 卸载

```bash
npx mm-gsd-core install --uninstall   # 移除已装技能,并清掉安装目录里的版本清单
```

## 边界

- 仓库是真理源,安装目录是派生产物:改了逻辑先改仓库,再同步到安装(发布走 npm;开发期可从仓库直接装,走与 npm 完全相同的安装路径)。
- 备份永远不落在技能目录里 —— 留在里面会被宿主注册成第二个技能。
- hooks 机制没验证过的宿主只装技能、不装 hook:宁可不装也不写坏宿主配置。
