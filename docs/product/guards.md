# 守卫

守卫是环境级的机器拦截:危险命令在**执行之前**被宿主 hook 挡下,agent 无法绕过。pre-commit 和检查器都管不到这一层 —— 危险发生在执行瞬间,必须在命令跑之前拦。

## 拦截哪些

安装时加 `--hooks` 即装(见[安装与更新](install-update.md)),本机所有项目生效。被拦的主要是破坏性 git 操作族:

| 操作 | 为什么拦 |
|---|---|
| `git reset --hard` | 丢弃未提交的工作 |
| `git clean -f` | 删除未跟踪文件 —— 在共享工作树里可能删掉别人的东西 |
| `git stash`(全族) | 存档区跨工作树共享,任何一侧的存取都可能搅乱兄弟会话的进行中工作 |
| 强推(`--force` / `-f`) | 覆盖远端他人提交;推荐的出路是 `--force-with-lease` 或先拉取 |
| 强删分支 / 引用 | 不可逆删除,确认已合并或已备份再删 |
| 全量重置工作区(`checkout .` / `restore .` / `checkout -f` / `switch --discard-changes`) | 一次丢掉所有未提交改动 |
| 推保护分支(main / master / develop) | 保护分支的变更走流程,不由单方强推(`--force-with-lease` 不拦) |

每条拦截都给理由:**为什么危险 + 出路是什么**。

## 行为边界

- **fail-closed**:事件解析失败按拦截处理 —— 守卫失效的时刻恰是危险命令穿过的时刻,「不能验证」不能当「不危险」。
- **绕过变体一并归一**:换着写法(如 `git -C <目录> reset --hard`)同拦 —— 对输入做归一化,不枚举变体。
- 守卫通道与遥测通道方向相反:守卫会阻断,遥测永远只记录、零阻断(见[遥测](telemetry.md))。

## 三层门禁各管一段

| 层 | 时点 | 强度 |
|---|---|---|
| 宿主守卫(本篇) | 命令执行前 | 环境级,agent 无法绕过 —— 真正不可替代的是这层 |
| 检查器 | 工件写完 | 流程级,见[校验](checking.md) |
| git pre-commit | 提交那一刻 | 可选,与项目现有 hooks 体系冲突时不要装 |
