# 五步环

项目按 phase 推进,每个 phase 走五步:**讨论(discuss)→ 计划(plan)→ 执行(execute)→ 验收(verify)→ 交付(ship)**;修不好就回执行重修(预算 2 轮)。

每一步收尾的动作是「跑检查器转绿」。每步都有落盘工件,机器从工件存在性推导真实进度 —— 声明与推导对不上,检查器当场判红(状态不能说谎)。

| 步 | 用户可见的行为 | 落盘物 |
|---|---|---|
| 讨论 | 把灰区决策逐条钉死,每条标可逆性;没有灰区也要写最小讨论工件;沉淀「用户原话一句话」作需求落点 | 讨论工件(CONTEXT) |
| 计划 | 目标倒推拆票:每张票带四件套(要改文件 / 做法 / 验证命令 / 完成判据)与失败方向;票数或单票文件数超预算是拆票,不是缩内容;规划完先过独立预审,阻塞问题清零才开工 | 计划工件(PLAN)+ 预审工件 |
| 执行 | 施工方照票施工,逐票原子提交;只核对「落的与图纸对不对得上」,不审批图纸;每票收尾跑票内验证命令,退出码即判据 | 收口工件(SUMMARY,提交号实测) |
| 验收 | 独立上下文验证:假设「任务完成了但目标落空」,逐条推翻;逐票给结论 | 验收工件(VERIFICATION) |
| 交付 | 交付物被真实消费;写「已交付」前先核对 PR / 合并 / 发布是真的 | 交付工件(SHIP) |

## 与五步配套的机器面

- **检查器**:每步收尾跑一遍,从工件推导状态并核对契约,见[校验](checking.md)。
- **预审**:计划复核由全新上下文的只读子代理做 —— 自己写自己审不算数;预审没过的计划进不了执行。
- **看板**:五步进度在过程看板的 phase 总览表里以五点呈现(工件在场即亮,判定以检查器为准),见[过程看板](board.md)。
- **验收不过**:已交付 phase 的单条细节缺陷走点修快速通道,不开新 phase,见[点修与报修](repair.md)。

## 边界

- 环的完整顺序只有流程总控一处持有;路由门禁盯着每个技能都写清了自己的下一步 —— 跑完一步不知道下一步敲什么,当场判红。
- 只有交付工件落盘才推出「已交付」;验证通过只是「已完成」,停在验证没走到交付会被检查器警告。
