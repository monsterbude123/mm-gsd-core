# 假绿门怎么自己变成假绿:从「零匹配判绿」到「教法与实现分叉」

日期:2026-11-15 · 相关:REQ-32..REQ-48 · phase 26(九张票 / 七轮独立验收)

## 结论先说

使用方报的一条 issue(「票级 verify 的 `-run` 零匹配假绿检测不到」)扩成了 phase 26 的九张票。
最后落地的不是一条规则,而是三层东西:

| 层 | 做了什么 | 代表决策 |
|---|---|---|
| **判据层** | 门禁怎么判一条 verify 是不是假绿 | D-13 三面口径(分类面/触发面/标记面) |
| **制度层** | 谁来执行、哪些票免判 | D-14 收口票免判、D-19 用例名必须真实存在 |
| **观测层** | 诊断准不准 | D-11 自测的失败不许混进 observe 的排行 |

七轮独立验收共挖出 **19 条 gap**(1 条阻断级)。回头看,**没有一条是「规则没写」**——
全都是「规则写了但没人执行」或「写的人和执行的人口径不一样」。

## 七条教训

### 1. 门禁认不出「这条命令真的跑过什么」→ 判定拆三面

同一个 `verify:` 文本,三个问题必须分开答:

| 面 | 答什么 | 认错的后果 |
|---|---|---|
| **分类面** | 这段命令**是什么**(看骨架:剥掉引号内容) | `grep -v "x"` 被当成断言来源 |
| **触发面** | 这段命令**会不会真的跑**那件事(看真正会执行的命令) | `bash -c "cargo test -- x"` 里的命令整段消失 |
| **标记面** | 断言词**从哪来**(看匹配器的模式串) | `echo "3 passed"` 自己造标记 |

26-04 ↔ 26-05 之间在「分类用骨架、触发用原文」之间摇摆,长出了两个方向相反的洞:
一个漏放行(wrapper 载荷消失),一个误伤(引号里的字面量被当命令)。
**一个判定只有一个口径,不能让两个面各读一份文本。**

### 2. 文本匹配的假阴性:名字在源码里出现过就算「存在」

新加的「票面 verify 引用的用例名必须真实存在」这道门,靠的是在自测源码里找这个名字。
于是:名字写在**注释**里也算存在;写在**别的夹具**里也算存在。
假阴性确凿,但**不构成绕过** —— 门只加红,加错了顶多多报一条。
反过来,如果这道门去**执行**票面 verify,那就不叫门禁了(verify 是任意命令,动辄几十秒)。

### 3. 恒红的门不是严,是废

本仓的 `.planning/` 是历史档案。全量 `--plan` 扫描 25 条红,全落在 phase 01–08 的旧票上
(引用了早删的文件、缺 done、老票之间撞文件)。这条门永远绿不了 → 没人看它 → 它什么都不挡。
`skills/mm-gsd-loop/references/ticket-alive.mjs` 文件头早就写着这句,但**只有漂移门与决策核销门**
按它跳过已收口的票,**票级门与批图门漏了**。补上之后:全量扫描 25 → 0 条红。

### 4. 声明式标记,不猜路径

自测夹具跑检查器 → 检查器把自己「STATE 声明与推导不符」写进共享遥测 → observe 的诊断排行
被自己的自测噪声淹没:1488 条失败里 **1303 条(87.6%)是临时目录里的自测夹具**,
而「跨 236 个项目」那条系统性结论**一条都不剩**。
修法不是「看路径像不像临时目录」(那会把真项目误排除),而是**让自测自己声明 sandbox**。

### 5. 教法与实现必须同源(两次分叉各被抓一次)

第一次:文档教 `cargo test -- --test-threads=1` 是「过滤器形态(须写判别性断言)」,
实现判它是**全量套件** → 照文档写的票被判红,门禁回「搬到 batch_verify」。
第二次:升级说明里写「写了判别性断言的存量票升级后会开始被零匹配门判红」——
**方向正好相反**:写了真断言的不受影响,被判红的是**没写断言**和**只写零匹配签名**的。
**教法是门禁的一部分**,不同源就等于给使用者发一份错的说明书。

### 6. 纪律写了但没有机器门 = 没写

`skills/mm-gsd-exec/SKILL.md` 一直写着「提交前必须跑本任务 `<verify>` 且退出码 0」。
但全仓没有任何机器门执行票面 verify —— 那段是散文。
26-05 那张票的 verify **至今是红的**(用例名写错),而没人发现,直到独立验收去逐字对名字。
补的门不是「替用户跑 verify」(太贵),而是「verify 里引用的用例名必须真实存在」(静态、便宜、只加红)。

### 7. 文档里写「全称词」必然写错 → 给规则 + 指针

升级说明改了三轮还是被打回:每一轮都是「有一类形态没被提到」或「有一句写反了」。
最后改成「**凡是按用例名收窄的命令**必须写判别性断言」+「照上面几段改写,改完跑一次 `--plan` 看还红不红」——
**规则兜住全集,例子只是举例,出路是让人自己跑一遍看**。

## 还欠着的账

- 「票面 verify 必须 exit 0」仍然是人工项(机器只校名字存在,不替你跑命令)。
- 门禁认不出「断言词来自哪条命令的输出」(跨命令的输出血缘)——只能靠教法兜。
- 收口豁免的信任面:一张手写的 `NN-MM-SUMMARY.md`(`status: complete`)就能给某张票免判。
