# 报修闭环:三次差点关门禁的静默失败

日期:2026-10-19 · 版本:0.2.0 · 相关规则:R-13 / R-14 / R-06 / R-01 / T-03

## 目标

给使用 mm-gsd 的 agent 一条报修通道,再把「拉取 → 修复 → 发布 → 关闭」接成闭环。
做法:`npx mm-gsd-core report` 报修,`mmc inbox` 拉取,`mmc close` 关闭。

## 建成时踩到的三个静默失败

它们的共同点是:**打印出来的一切都正常**。

### 一、label 对不上,维护方永远看不见

报修入口打 `mm-gsd-agent`,`inbox` 按 `mm-gsd` 过滤。第一版拉回来 3 条里只有 1 条,
输出是:

```
✓ I-002 ← GitHub #1 ...
  新落 0 条,已在本地 1 条
  没有新问题要处理
```

「新落 0 条」看起来像没事,实际是**没看见**。而且拉取侧和上报侧是两个文件里的两处字符串,
没有任何机制保证它们一致。

改法:不按 label 过滤,只取 open,本地按 `github:` 行去重。多拉的会在去重时消失。

> 两个方向的字符串要靠人记着一致,它们迟早会不一致。凡是"两个地方必须对齐"的规则,
> 都要么让机器推导,要么让错误的代价显式可见。

### 二、证据提取失败,写了个占位符

第一版证据提取只认围栏块,匹配不上就写 `(issue 里没贴证据)`。而真实 issue 用缩进块。
结果是每条导入的 issue 证据都是那句占位符 —— 而 R-01 证据门禁判的是
"## 证据节存在且非空",占位符完全满足。

**门禁对着假证据说通过,比没有证据更坏**:它把"我知道这里没证据"变成了"这里有证据"。

改法:先找围栏块,再退到缩进块,都没有就写明"没提取到证据,请补"。

### 三、R-01 自己的判据太窄,误伤了真证据

上面那条修完,使用方提交的真实复现步骤还是被判"没有证据"。
R-01 原来的判据是一串关键词白名单(`复现|报错|mm-gsd-runs.jsonl|$|>`),
使用方的复现句子里一个都没有。

有意思的地方:**误报只会在维护方这边红**。使用方提交完就走,永远不知道自己踩的坑
没被接住。门禁红了没人看见,等于没红。

改法:判据换成「证据节存在且有实质内容」。放宽之后必须证明还能咬人 ——
造两条违规 issue(空证据节、无证据节)验证都报红,这一步不能省。

## 拆文件

`mmc.mjs` 撞到 700 行单文件上限。按本仓库「变胖必须有等量删除」的做法,
没有抬上限,而是把 GitHub 往返拆进 `tools/gh-issues.mjs`。

拆的时候顺手补了 R-06 的一个洞:零依赖检查只扫静态 `import`,
藏在函数里的动态 `import("./nope.mjs")` 加载期不崩、运行到才炸,检查器看不见。
静态 import 写错路径 Node 加载时就崩(红得响),所以两种都得扫。

验证时又发现:造违规样例会让 health 自己崩溃 —— `import "lodash"` 在加载期就抛,
根本走不到检查逻辑。**这说明门禁对"自己加载不了"没有防护**,
现在靠 Node 自身的加载失败(退出码非零)兜住,红是红了,只是不好看。

## 一句话

> 「新落 0 条」和「门禁通过」是最危险的两种输出 ——
> 它们都长得像"一切正常",实际是"什么都没发生"。
