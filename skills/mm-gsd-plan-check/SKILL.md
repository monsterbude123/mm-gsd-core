# MM-GSD 显式校验计划(plan-check)

**你是校验的调度方,不是计划的作者,也不是它的辩护人。** 用户要的是一个确定答案:
**这份计划现在能不能开工**。别凭印象回答,别因为 plan 说「我检查过了」就放行 ——
机械合规过了不等于计划成立,自评不算数。这个技能存在的理由:预审不该藏在流程里等人走到那一步,
它是一条用户随时可以主动敲的操作。

## 输入:锁定要校验的那份 PLAN

- 用户给了路径 → 用路径。
- 用户只给了票号(如 `10-01`)→ 拼 `.planning/<票号>-PLAN.md`,存在就用。
- 什么都没给 → 列出 `.planning/` 下的 `*-PLAN.md`(双布局都看:根级与 `phases/<dir>/`)让用户挑,**别猜**。

## 输入面白名单(预审读什么,不读什么)

预审的输入只有这五样:**PLAN、CONTEXT、REQUIREMENTS.md、codebase-map.md、机器门输出**(`--plan` / `--plan-check` 的结论行)。
**禁止全仓扫描与 grep 代码** —— 预审重复研究是实测耗时大头;「代码现状与 PLAN 前提失真」由 plan 的实测纪律兜,预审不兜(D-04)。
`codebase-map.md` 缺失时按其余工件判,并在发现清单里注一条 INFO —— 地图缺失本身不拦。
读地图也一样:**消费它,不重建**(入口级一屏,过期丢掉重做)。

## 三步,顺序不可换

### 第 1 步:跑机器判据 —— 退出码就是结论的一半

```
node ~/.agents/skills/mm-gsd-loop/scripts/gsd-state-check.mjs --plan-check .planning/<NN-MM>-PLAN.md
```

- **退出码 0** = 机器判据全过 **且** 预审工件 `passed` → 向用户报「✅ 可以开工」并给出预审工件路径,结束。
- **退出码 1** → 照输出走第 2 步。**不要**用自己的解读替代命令结论 —— 结论行(`✅ 可以开工` /
  `⛔ 不能开工`)与退出码才是答案,你的转述不是。
- 这条命令对 `.planning/` **只读不写**:它不会替你生成预审工件。(检查器自己会把遥测写到家目录
  `~/.agents/`,与项目工件无关,`GSD_TELEMETRY=0` 可关。)工件缺失时它会把该派的提示词打印在输出里。

### 第 2 步:预审缺失或 blocked → 派独立复核(自己写自己审不算数)

- **你能派子代理** → 派一个**全新上下文的只读子代理**。**宿主装了 `mm-gsd-plan-reviewer` 卡就用卡派
  (它被物理限制为只读:tools: Read, Grep, Glob);没有卡才按提示词派,并在 prompt 里声明工具限 Read/Grep/Glob。**
  提示词用第 1 步输出里打印的那段(判据权威在 `mm-gsd-verify` 的「执行前预审」节:六个维度、severity 必填、
  写不变式、只报不处方)。**第一维的 REQ 基线:以 REQUIREMENTS.md 的 REQ 清单为基线对账,不只对账 CONTEXT D-NN**
  —— 没被认领的 REQ 是 BLOCKER(机器门 checkReqCoverage 会判)。**子代理只返回发现清单文本,不写任何文件;PLAN-CHECK 工件
  (`.planning/<NN-MM>-PLAN-CHECK.md`,`status: passed|blocked`)由你落盘**(phase 11 D-01 附带设计)。
  **它多半没有再派子代理的能力 —— 复核由它亲自读 CONTEXT / PLAN / REQ 完成,这不是缺陷,是设计。**
- **你不能派子代理**(你多半就是被派出来的那一个)→ **停下,把提示词原样交回编排层或用户**,
  让编排层派。不派预审就宣布「通过」= 预审门被你自己拆了 —— 这条没有例外。
- **有界修订 ≤2 轮**:BLOCKER 交回 plan 修(要改决策才回 `mm-gsd-discuss`),修完重跑第 1 步;
  两轮 issue 数不降 → 停下升级到人,别再兜圈。INFO 照列但不挡。

### 收敛判据(第 2 步的修复循环按此收口,issue #13)

- `机器门禁绿 ∧ 一轮独立预审零 BLOCKER` ⇒ **允许开工**(进第 3 步拿退出码收口)。
- 每条 WARNING:逐条**归 Deferred**(写进 SUMMARY 的 Deferred Issues)带进施工 —— 不为它开新一轮改稿。
- **轮次硬上限 2**:第 3 轮仍报 BLOCKER → **停下升级**(改 scope,或判定该批不做),不继续改稿 ——
  与 exec「同根因 ≤2 次」同一纪律;复审的价值是发现新事实,不是重复确认既有结论。

### 第 3 步:重跑第 1 步,拿退出码收口

- 退出码 0 → 报「✅ 可以开工 —— 机器判据全过 + 预审 passed」+ 预审工件路径。
- 仍非 0 → 把没清零的项**原样**报给用户:证据是命令输出与 PLAN-CHECK 的 findings 原文,
  不是你的转述。停在「⛔ 不能开工」,不进执行。

## 点修轻量预审(R 票专用)

点修票(`.planning/<NN>-Rk-PLAN.md`,挂原 phase)走**轻量预审**,不全维审 —— 修复票天生继承原 phase 已定决策面,全维审是重复劳动:**只审三件**

1. **重验目标明确**:verify 指名要重验的那条 truth(引用原 VERIFICATION 的 truth 编号/名字),不写「修好再说」;
2. **范围 ≤5 文件**:files_modified 超过 5 个就是升级信号,不是点修;
3. **不扩 scope**:不新增 REQ、不改 CONTEXT 的 D-NN —— 修复若推翻决策,升级新 phase 走完整循环。

其余维度(REQ 基线对账、研究消费、批图并行)对 R 票免审(机器门已放行:R 票不进批图、不触发研究门)。**复审 ≤2 轮**,与主预审同一上限;R 票 ≥3 张时 checker 会黄提醒强制升级 —— 预审看到该提醒应直接建议升级而不是继续放行。

## 红线

- **不修计划**:发现是预审的事;改法归 plan,拍板归 discuss。你只校验、只转交。
- **不替子代理写结论**:PLAN-CHECK 工件只能由独立复核落盘 —— 脚本能写、调度方能写,就等于自己判自己。
- **不降级**:「计划很简单,不用预审了吧」不是你的决定 —— fail-closed,看不清的状态一律当不能开工。
- **不复用结论**:`PLAN-CHECK` 的 `plan:` 字段必须是**这一张票**的票号;改了 PLAN,上一轮结论作数作废,重审。

## 完成后

- 这一步做完的判据:`--plan-check` 退出码 0(机器判据全过 + 预审工件 `passed`),且结论已如实报给用户
  (能开工给工件路径;不能开工给 findings 原文)。
- **下一步:退出码 0 → 编排层调 `mm-gsd-exec` 进施工;仍非 0 → 停在「⛔ 不能开工」**,BLOCKER 交回
  `mm-gsd-plan` 修(要改决策才回 `mm-gsd-discuss`),复审走「收敛判据」节(轮次硬上限 2)。
- 例外:预审轮次打满仍不降 → 升级到人,不自行豁免(豁免是编排层按全局决策权规则显式记录的动作,不是默认)。
- 环的完整顺序只有 mm-gsd-loop 持有,这里只写自己这一步的出口。
