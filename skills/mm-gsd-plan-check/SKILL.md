# MM-GSD 显式校验计划(plan-check)

**你是校验的调度方,不是计划的作者,也不是它的辩护人。** 用户要的是一个确定答案:
**这份计划现在能不能开工**。别凭印象回答,别因为 plan 说「我检查过了」就放行 ——
机械合规过了不等于计划成立,自评不算数。这个技能存在的理由:预审不该藏在流程里等人走到那一步,
它是一条用户随时可以主动敲的操作。

## 输入:锁定要校验的那份 PLAN

- 用户给了路径 → 用路径。
- 用户只给了票号(如 `10-01`)→ 拼 `.planning/<票号>-PLAN.md`,存在就用。
- 什么都没给 → 列出 `.planning/` 下的 `*-PLAN.md`(双布局都看:根级与 `phases/<dir>/`)让用户挑,**别猜**。

## 三步,顺序不可换

### 第 1 步:跑机器判据 —— 退出码就是结论的一半

```
node ~/.agents/skills/mm-gsd-loop/scripts/gsd-state-check.mjs --plan-check .planning/<NN-MM>-PLAN.md
```

- **退出码 0** = 机器判据全过 **且** 预审工件 `passed` → 向用户报「✅ 可以开工」并给出预审工件路径,结束。
- **退出码 1** → 照输出走第 2 步。**不要**用自己的解读替代命令结论 —— 结论行(`✅ 可以开工` /
  `⛔ 不能开工`)与退出码才是答案,你的转述不是。
- 这条命令**只读不写**:它不会替你生成预审工件。工件缺失时它会把该派的提示词打印在输出里。

### 第 2 步:预审缺失或 blocked → 派独立复核(自己写自己审不算数)

- **你能派子代理** → 派一个**全新上下文的只读子代理**,提示词用第 1 步输出里打印的那段
  (判据权威在 `mm-gsd-verify` 的「执行前预审」节:六个维度、severity 必填、写不变式、只报不处方)。
  子代理把结论落盘到 `.planning/<NN-MM>-PLAN-CHECK.md`(`status: passed|blocked`)。
  **它多半没有再派子代理的能力 —— 复核由它亲自读 CONTEXT / PLAN / REQ 完成,这不是缺陷,是设计。**
- **你不能派子代理**(你多半就是被派出来的那一个)→ **停下,把提示词原样交回编排层或用户**,
  让编排层派。不派预审就宣布「通过」= 预审门被你自己拆了 —— 这条没有例外。
- **有界修订 ≤2 轮**:BLOCKER 交回 plan 修(要改决策才回 `mm-gsd-discuss`),修完重跑第 1 步;
  两轮 issue 数不降 → 停下升级到人,别再兜圈。INFO 照列但不挡。

### 第 3 步:重跑第 1 步,拿退出码收口

- 退出码 0 → 报「✅ 可以开工 —— 机器判据全过 + 预审 passed」+ 预审工件路径。
- 仍非 0 → 把没清零的项**原样**报给用户:证据是命令输出与 PLAN-CHECK 的 findings 原文,
  不是你的转述。停在「⛔ 不能开工」,不进执行。

## 红线

- **不修计划**:发现是预审的事;改法归 plan,拍板归 discuss。你只校验、只转交。
- **不替子代理写结论**:PLAN-CHECK 工件只能由独立复核落盘 —— 脚本能写、调度方能写,就等于自己判自己。
- **不降级**:「计划很简单,不用预审了吧」不是你的决定 —— fail-closed,看不清的状态一律当不能开工。
- **不复用结论**:`PLAN-CHECK` 的 `plan:` 字段必须是**这一张票**的票号;改了 PLAN,上一轮结论作数作废,重审。
